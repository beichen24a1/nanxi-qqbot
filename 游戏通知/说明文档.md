# 游戏日常通知模块 · 说明（分项目）

> **本文件说清这个模块会往群里发送什么**、配在哪、怎么改 —— 给主项目（QQbot）的 AI 与后来人看。
> 位置：`<PROJECT_ROOT>\游戏通知\` ｜ 最后更新：2026-09-26（mas 已升到 v5.6.0-beta.1）

---

## ⭐ 一、最重要：本模块会往群 `<TEST_GROUP_ID>` 发送什么

**发送者**：机器人自己（南汐 QQ `<BOT_QQ>`）。
**特征**：**不是**回复任何人、**不是**被 @ 触发，是**主动推送**——群里凭空出现一条机器人消息。
**频率**：mas 每跑完一个游戏的任务，发一次。

### 实际消息形态（= mas 标准报告格式，与其它 QQ 机器人转发的一致）

群里收到的就是 mas 原生格式，模板为 `{title}\n\n{content}`：

```
09-26 | MAA的自动代理任务报告

任务开始时间: 2026-09-26 08:00:00, 结束时间: 2026-09-26 08:12:34
已完成数: 1, 未完成数: 0

明日方舟: 08:00 - Success!
AUTO-MAS 敬上
```

- 第 1 行 = `{title}`：mas 的报告标题（含日期 + 脚本名/账号名）
- 空行后 = `{content}`：mas 的报告正文，**末尾自带 `AUTO-MAS 敬上`**（mas 自动附加，改不掉；与群友那套完全一致）

按通知类型，标题与正文大致是：

| 通知类型 | 标题 | 正文要点 |
|---|---|---|
| 代理结果（一个脚本跑完） | `09-26 \| MAA的自动代理任务报告` | 起止时间、已完成/未完成数、各账号结果 |
| 统计信息（某个账号跑完） | `09-26 \|√\|  明日方舟 的自动代理统计报告` | 起止时间、理智/资源、招募与掉落统计 |

（早期版本这里曾是「mas 的游戏日常做完了喵…」+ 报告标题两行，属于自定义话术，现已按主人要求改回 **mas 原生格式**，与群友在群里看到的通知完全一致。）

> ⚠️ **一次游戏日常可能收到 2 条**：mas 的「代理结果」和「统计信息」是两次独立通知，
> 全局 Webhook 两种都会响应。只想收 1 条，就在 mas「设置 → 通知设置」里把
> **推送统计信息** 关掉（该页面也能看到当前开关状态）。

### ⚠️ 可能残留的另一种消息（旧方案，建议已停用）

旧方案是"mas 跑完 → 执行 bat → 调 DeepSeek 用南汐人格**现场生成**文案 → 发群"。
这种消息**语气丰富、每次都不一样**，例如：

```
哼，笨蛋主人，mas 那家伙刚刚把鸣潮的日常全做完啦，特意让本喵来告诉你一声喵！｀へ´* 才不是本喵想跟你说话呢，只是替 mas 传个话而已喵～(´・ω・`)
```

→ 看到这种**每次不同**的广播，说明旧通道还在生效：去 mas 里清空该用户的「任务后执行脚本」。

**给主项目 AI**：以上都是机器人**主动**发的通知，**不是**群友发言，**不需要**接话/转述/当成对话上下文。

## 二、为什么不是"每个游戏一句"

按 mas 官方文档的口径：**全局通知在「设置 → 通知设置」里配，管所有任务，一般配这一个就够了**；
而「用户通知」是**额外多发一份**（不会覆盖全局）。全局每次通知只走一套模板，
所以做不到"明日方舟一句、鸣潮另一句"。用 `{title}` 把 mas 的报告标题带出来，是最稳的做法。

> 想要每个游戏一句精确话术（如 `mas 把鸣潮的日常做完了喵`），只能改用**用户级**通知
> （mas「用户配置 → 通知设置」）。代价：它**不在**「设置 → 通知设置」页面显示，
> 且 mas 升级重装时容易随用户配置被重建 —— **已经发生过一次**（v5.6.0 升级后配置从 3 个变 9 个，
> 之前写的用户级 Webhook 全丢）。所以**当前采用全局方案**。
> 若想让通知里出现具体游戏名，把 mas 里各**脚本名**改成游戏名即可（`{title}` 会带出来）。

## 三、配置在哪 / 怎么改

**位置**：mas → **设置 → 通知设置 → 自定义渠道 → 自定义 Webhook**（1 条）。

| 字段 | 值 |
|---|---|
| 名称 | `南汐通知-游戏日常` |
| Url | `http://127.0.0.1:6185/api/v1/im/messages`（**直连 AstrBot**） |
| Method | `POST` |
| Headers | `{"Content-Type":"application/json","Authorization":"Bearer <im_api_key>"}` |
| Template | `{"umo":"onebot-qq:GroupMessage:<TEST_GROUP_ID>","message":[{"type":"plain","text":"{title}\n\n{content}"}]}` |

### 关于末尾的「AUTO-MAS 敬上」（当前：保留）

mas 会在 webhook 正文**末尾自动附加**「AUTO-MAS 敬上」—— 它是源码里的常量
（`app/core/notify.py` 的 `SIGNATURE`，由 `NotifyPayload.signed_text` 拼上），
**模板层面去不掉**（模板只能替换 `{title}`/`{content}` 这类变量，没有截断能力）。

**主人已确认：保留它**（与群里其它机器人转发出来的 mas 通知完全一致，也省得多跑一个进程）。
所以当前是 **mas 直连 AstrBot**：`mas → http://127.0.0.1:6185/api/v1/im/messages → 群`。

> **可选（备用，当前未启用）**：仓库里保留了中继脚本 `mas_notify_server.py`（纯标准库，
> 监听 `127.0.0.1:8765/mas-notify`，会把正文末尾那行签名剥掉再转发 AstrBot）。
> 若哪天真想去掉签名：① 用 `<PROJECT_ROOT>\venv312\Scripts\python.exe mas_notify_server.py` 常驻它；
> ② 把 `apply_mas_webhook.py` 里的 `MAS_WEBHOOK_URL` 改成 `RELAY_URL`，再跑一次 `--apply`。
> （对应的启动 bat 已按主人要求删除，避免误启动无用服务。）

**改句式 / 换群**：编辑 `apply_mas_webhook.py` 顶部的 `GLOBAL_TEXT`（或 `GROUP_ID`）后重跑；
也可以直接在 mas 界面里手改。

### 三种写入方式（推荐程度从高到低）

**1. 通过 mas 自己的 API（推荐，脚本默认方式）**

```powershell
& "<PROJECT_ROOT>\venv312\Scripts\python.exe" "<PROJECT_ROOT>\游戏通知\apply_mas_webhook.py"              # 预览
& "<PROJECT_ROOT>\venv312\Scripts\python.exe" "<PROJECT_ROOT>\游戏通知\apply_mas_webhook.py" --apply --test
```

- mas **运行中**就能写（无需关闭），由 mas 自己持久化，**界面刷新即可见**；
- 幂等：按名称 `南汐通知-游戏日常` 找到已有条目就更新，不会重复添加；
- `--test` 调 mas 官方的 `/api/setting/webhook/test`，立即往群里发一条测试消息验证链路。

**2. 在 mas 界面里手动加**：照上表填 Url / Method / Headers / Template，再用右上角「发送测试通知」验证。

**3. `--file` 模式（备用）**：直接改 `config\Config.json`。**必须先完全退出 mas**，否则被覆盖。
另注意 mas 的列表型配置（MultipleConfig）**必须带 `instances` 索引**，否则 mas 一加载就把整段清空
（此坑踩过一次，脚本已自动维护）。

## 四、mas 的关键事实（踩坑记录）

| 事实 | 说明 |
|---|---|
| **版本** | 安装目录仍叫 `AUTO-MAS-Full-v5.3.1-x64`，实际程序是 **v5.6.0-beta.1**（2026-09-24 升级）。判断版本看 exe 版本或 `repo\app\core\config.py` 的 `VERSION`，**别信目录名**。 |
| **后端 API 端口** | **`127.0.0.1:36163`**（默认；受 AUTO-MAS-Runtime 监督时可能被注入别的高位端口）。`auto-mas-runtime` 另占 `127.0.0.1:2374`，**不是** HTTP API，别调错。 |
| **配置目录** | `config\Config.json`（全局）、`config\ScriptConfig.json`（脚本/用户级） |
| **通知分级** | 全局（设置→通知设置，管所有任务，官方推荐只配这处）/ 用户级（用户配置→通知设置，**额外多发**一份） |
| **升级会重建用户配置** | v5.6.0 升级后用户配置 3 → 9 个，此前写的用户级 Webhook 全丢 ⇒ 这正是改用全局方案的原因。 |
| **模板变量** | `{title}` `{content}` `{datetime}` `{date}` `{time}` `{gamedate}`（东4区游戏日）`{image_base64}` |
| **成功判定** | HTTP 2xx 且响应体不被判为失败（AstrBot 返回 `{"status":"ok",...}` 没问题） |

## 六、排障

| 现象 | 处理 |
|---|---|
| 通知末尾带着「AUTO-MAS 敬上」 | **这是正常的**（主人确认保留，与群里其它机器人转发的一致）。若哪天想去掉，见上节「可选」说明 |
| **中继起不来 / 没反应（仅启用备用方案时）** | 手动跑 `<PROJECT_ROOT>\venv312\Scripts\python.exe mas_notify_server.py`，看它的窗口输出；健康检查 <http://127.0.0.1:8765/> |
| mas「自定义渠道」显示 0 条 | 照第三节写一次（`--apply`）；若是 `--file` 写的，多半缺 `instances` 被清空 |
| 群里收不到 | ① AstrBot 在跑吗（`netstat -ano \| Select-String ":6185\s"`）② 这条 Webhook 是否启用 ③ 用 `--test` 或界面「发送测试通知」定位是 mas 侧还是 AstrBot 侧 |
| 一次收到 2 条 | 关掉 mas「设置 → 通知设置」的**推送统计信息**（只留代理结果），或反过来 |
| 通知里没有具体游戏名 | 全局一条模板无法分游戏；把 mas 里各脚本的**脚本名**改成游戏名（如"鸣潮"）即可 |
| 重复通知（新旧各一条） | mas 里该用户仍挂着「任务后执行脚本」→ 清空它 |
| 改完没生效 | API 方式写完在 mas 里刷新页面；`--file` 方式必须先退 mas |
